# 홈·대출 관리·설정 API 연결

기준: LoanRun-Backend develop `c48b965` (2026-11-20). 실제 컨트롤러·서비스·마이그레이션을 기준으로 연결했습니다.

## 실행

Git에서 제외되는 .env.local에 아래 값을 설정하고 개발 서버를 재시작합니다.

```dotenv
VITE_API_MODE=hybrid
VITE_API_BASE_URL=
VITE_BACKEND_PROXY_TARGET=https://dev-api.loanrun.shop
```

로컬은 http://localhost:5173에서 /api 프록시를 사용합니다. Vite 프록시는 개발 환경 전용이며 배포에서는 /api 역방향 프록시 또는 같은 사이트 API 주소와 정확한 CORS 설정이 필요합니다.

- mock: 기존 예시 데이터로 디자인 확인.
- hybrid: 홈·대출·설정의 구현된 API는 실서버. 홈 리포트는 아직 Mock이며 팀원 영역은 별도의 VITE_LIVE_FEATURES 설정에 따라 전환합니다.
- real: 모든 영역을 실서버로 전환하는 향후 모드. 미완료 API가 있어 현재는 권장하지 않음.

대출 예시 화면은 source=mock 또는 preview 쿼리로 명시적으로 분리합니다. 실제 서버 오류를 Mock으로 바꾸지 않습니다.

## 연결 범위

| 화면 | 실서버 연결 |
| --- | --- |
| 홈 | 프로필·요금제, 실제 보유 대출·원금·진행률, 이번 달 납부 일정, 재정 위험도·금리/소득/지출 임계값. 기록 버튼은 실제 대출 관리 화면으로 이동 |
| 내 대출 | 목록·상세, 직접 입력 등록, 이름/기관/잔액/납부일/은행 안내 납부액 수정, 삭제, 금리 이력 조회·기록 |
| 이번 달 상환 | 일정·달력·납부 내역, 실제 정기/추가 납부 등록, 미납 확인 |
| 상환 내역 | 목록·상세, 서버 editable 권한에 따른 수정·삭제, 여러 페이지일 때만 이전/다음 표시 |
| 구간 기록 | 월별 통계. 미확인 실적·목표는 —이며 확인된 금액만 그래프에 전달 |
| 개별 계획 | 조회·미리보기·저장. 계획 수정은 한 대출씩 선택. BULLET은 목표일/만기 적립 분기 사용 |
| 적립 | 목록·등록·수정·삭제. 원금 상환과 구분하며 잠긴 기록은 변경 버튼 비활성화 |
| 전체 계획 | PRO 조회·현재 월 배분 저장. 서버의 실제 적용 상태만 표시하며 전략 후보를 만들지 않음 |
| 설정 | 프로필·요금제·Pro 전환·알림, 기존 재정 프로필 조회/수정, 지출 입력, CSV 다운로드 |

상품 캐시는 아직 503이 발생해 실제 등록은 직접 입력 방식(product_id=null)으로 시작합니다. 대출 유형은 백엔드 enum과 같은 표시용 목록이며 금액을 생성하지 않습니다. 재정 프로필 404에서도 피그마의 네 행을 유지하며 값은 —, 편집은 비활성화합니다. 기본 재정정보 최초 입력은 기존 온보딩에서 담당하고 설정에 별도 입력 버튼이나 모달을 추가하지 않습니다. 다른 오류는 표시합니다. 입력하지 않은 재정값을 자동 저장하지 않습니다.

전략 후보/리포트는 미완성이며 실제 전체 전략 적용은 별도 의존성이 필요합니다. 로그인·로그아웃·회원 탈퇴 API는 없으므로 hybrid에서 호출하지 않습니다. Pro 전환은 백엔드 DEMO_MODE가 필요하고 실제 결제는 연결하지 않았습니다.

## 계약과 파일

실서버는 HttpOnly LOANRUN_SESSION 익명 세션 쿠키를 credentials: include로 전송하고 Bearer 헤더는 붙이지 않습니다. 최초 병렬 요청 전 프로필 조회를 공유해 세션을 먼저 만듭니다. 응답 envelope의 success/code/message/data를 검사하고 오류 코드를 보존합니다.

금액은 JSON 숫자, 요청은 snake_case, 실제 수정/저장에는 서버가 요구하는 Idempotency-Key를 사용합니다. 계획은 서버 preview_version을 저장 요청에 전달하며 동일 미리보기 재시도에는 키를 유지합니다. 납부 수정에는 loan_id를 보내지 않고 DELETE에는 본문을 보내지 않습니다. 금융 계산은 서버 응답만 사용합니다.

납부 세부 내역을 직접 수정하지 않으면 원금/이자/수수료 필드를 생략해 서버가 저장된 의무 기준으로 계산합니다. 미리보기 예상액을 확정 내역으로 보내지 않습니다. 직접 수정하면 네 구성 금액을 모두 숫자로 보내고 총액 일치를 확인합니다. 정기 납부 회차는 납부일 월로 추측하지 않고 대출 상세의 가장 오래된 미납 next_payment를 사용합니다. 현재 납부 API는 memo를 지원하지 않으므로 사용자 요청대로 납부 메모 입력란을 제거했습니다.

홈 재정 위험도는 GET /api/risks/를 카드 단위로 조회합니다. FREE는 요청 없이 기존 잠금 UI를 표시합니다. PRO는 서버 level과 rate_thresholds/income_thresholds/expense_thresholds를 사용하며 기본 상환(basic_at_risk_from) / 추가 상환 유지(reduce_extra_from) 순서로 %p/감소율 %/증가 금액 원을 표시합니다. 0과 null은 구분하며 위험 점수·임계값을 프런트에서 계산하지 않습니다. 오류는 카드 안 기존 설명 위치에 표시하고 다른 홈 조회를 막거나 Mock으로 대체하지 않습니다. 서버가 PRO_REQUIRED를 반환하면 잠금 상태를 적용합니다. 실서버 FREE의403은 확인했으며 실제 PRO 수치의 성공 여부는 위험 이력 활성화 및 서버의 사용자 데이터에 따라 별도 검증이 필요합니다.

홈 이번 달 상환의 동그라미는 hybrid에서 실제 납부 API와 연결됩니다. 미완료 회차 클릭 시 outstanding_amount만 오늘 날짜의 REGULAR 납부로 등록하고, 성공 후 일정·원금·위험도를 다시 조회합니다. 추가 상환 목표액을 자동 납부하거나 원금·이자·수수료 구성을 추정하지 않습니다. 실패 시 체크를 바꾸지 않고 기존 요약 위치에 오류를 표시합니다. 중복 클릭을 차단하며 통신 재시도에는 같은 요청/Idempotency-Key를 유지합니다.

체크 취소는 해당 동그라미로 생성한 payment_id만 삭제합니다. 사용자별 sessionStorage에 생성 응답 영수증을 보존해 새로고침 뒤에도 구분하며, 삭제 전 상세 조회로 수정·잠금 여부와 원본 일치를 확인합니다. 기존 납부나 이후 수정된 기록은 임의 삭제하지 않습니다. 원본이 이미 삭제됐으면 다시 쓰지 않고 서버 상태를 새로 조회합니다. 로컬 계약 서버 브라우저에서 등록·취소·실패·중복 클릭·새로고침과 원금 갱신을 검증했으며 실제 배포 서버에는 검증용 납부를 생성하지 않았습니다.

- createRuntime.js: 실서버 허용 경로·세션 초기화·Mock 분리
- services.js, loanRequest.js: API 계약과 입력 DTO
- loanWorkspace.js: 화면별 필요한 조회만 조합, catalog/schedule 장애가 무관한 화면을 막지 않음
- Loans.jsx: 기존 JSX와 Sass 화면을 재사용하는 실제 조회·변경 흐름

## 검증 및 제한

홈 리포트 진입 영역은 hybrid에서 GET /api/reports/latest/를 독립 조회합니다. FREE는 요청 없이 잠금 안내를 표시하고, PRO_REQUIRED 응답도 잠금으로 처리합니다. 생성 중/실패/미생성/갱신 필요 상태는 기존 설명 위치에 표시합니다. N 배지는 COMPLETED이고 stale=false이며 서버 생성 시각 기준 24시간 이내인 경우에만 표시합니다. 조회 오류는 다른 홈 영역을 막지 않으며 Mock으로 대체하지 않습니다. hybrid 홈은 더 이상 Mock dashboard/loans/plans를 조회하지 않습니다. 리포트 생성 요청은 하지 않으며 진입 버튼은 기존 /reports로 이동합니다.

```sh
node --test src/api/__tests__/runtime.test.js
npm run build
npm run lint
```

API 계약/화면 테스트는 로컬 임시 HTTP 서버를 사용합니다. 실제 배포 서버 읽기 확인에서 일정/통계/계획(빈 대출)/CSV는 200이며 새 세션 재정 프로필은 미등록404, 상품 캐시는503입니다. 이 결과는 실제 대출이 있는 상태의 저장·수정·삭제 성공 검증을 의미하지 않습니다.

배포 서버에 테스트 금융 데이터를 생성·수정·삭제하는 검증은 자동 승인 검토에서 외부 데이터 변경 및 잔여 데이터 위험으로 차단됐습니다. 해당 실서버 쓰기 검증은 별도 사용자 승인이 필요합니다. verification 결과물과 로컬 환경 파일은 Git에서 제외합니다.
