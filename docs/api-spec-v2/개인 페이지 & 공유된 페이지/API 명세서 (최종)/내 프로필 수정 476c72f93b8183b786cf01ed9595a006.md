# 내 프로필 수정

API Endpoint: /api/users/me/
FE 연동: No
HTTP method: PATCH
Status: BE 구현전
Test: No
model: users
메모: G1 이름·직업·소득 유형 수정.
순서: 6

**기능:** 내 프로필 수정

**HTTP method:** `PATCH`

**API Endpoint:** `/api/users/me/`

**인증:** 필수 (Authorization: Bearer {access_token})

## Request

| 필드 | Type | 필수 | 설명 |
| --- | --- | --- | --- |
| name | string | 선택 | 1~50자 |
| occupation | string 또는 null | 선택 | 직업명, 최대 50자 |
| income_type | string | 선택 | REGULAR 또는 IRREGULAR |

**요청 예시**

```jsx
PATCH /api/users/me/
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
{
  "name": "민준",
  "occupation": "프리랜서",
  "income_type": "IRREGULAR"
}
```

## Response

### 성공 200

```json
{
  "success": true,
  "code": "USER_UPDATE_SUCCESS",
  "message": "프로필을 수정했습니다.",
  "data": {
    "user_id": 1,
    "email": "demo@example.com",
    "name": "민준",
    "occupation": "프리랜서",
    "income_type": "IRREGULAR",
    "onboarding_completed": true,
    "plan_type": "PRO"
  }
}
```

**data 필드** (중첩 객체는 JSON 예시와 공통 스키마 기준)

| 필드 | Type | 정의 |
| --- | --- | --- |
| `user_id` | integer | 사용자 식별자 |
| `email` | string | email 값(공통 규약) |
| `name` | string | name 값(공통 규약) |
| `occupation` | string | occupation 값(공통 규약) |
| `income_type` | string | income type 값(공통 규약) |
| `onboarding_completed` | boolean | onboarding completed 값(공통 규약) |
| `plan_type` | string | FREE 또는 PRO |

### 실패 응답

**실패 400 · VALIDATION_ERROR**

```json
{
  "success": false,
  "code": "VALIDATION_ERROR",
  "message": "입력값을 확인해 주세요.",
  "errors": {
    "name": [
      "빈 값은 허용되지 않습니다."
    ]
  }
}
```

**실패 401 · AUTH_REQUIRED**

```json
{
  "success": false,
  "code": "AUTH_REQUIRED",
  "message": "로그인이 필요합니다.",
  "errors": {}
}
```

## `GlobalExceptionHandler.java` 처리 기준

| HTTP status | code | message |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 입력값을 확인해 주세요. |
| 401 | `AUTH_REQUIRED` | 로그인이 필요합니다. |

공통 예외 응답은 프로젝트 공통 규약을 따릅니다. 동일 HTTP status여도 발생 원인에 따라 code를 구분합니다.

## 처리 규칙 및 개발 참고

- PATCH는 전달 필드만 수정. 소득 유형 변경 시 budgets/profile PUT으로 소득 유형과 필수값을 함께 저장(프로필 있으면 불일치 변경 거부 400). 기존 월 스냅샷 보존.

**화면/기능 연결:** G1 이름·직업·소득 유형 수정.

- 소득 유형 변경은 기본 재정정보와 정합성 검증 후 현재·미래 미확정 월부터 적용; 과거 월 및 입금 기록 보존.
