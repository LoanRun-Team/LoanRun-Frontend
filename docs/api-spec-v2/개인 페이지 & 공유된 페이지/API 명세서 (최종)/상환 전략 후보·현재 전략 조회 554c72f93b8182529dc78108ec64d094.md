## 처리 규칙 및 개발 참고

- 활성 대출 수와 유형에 따라 strategy_type MULTI/SINGLE_PREFERENCE/SAVINGS_ONLY/NONE. 최신 완료 리포트가 stale/미완료면 후보 빈 배열, unavailable_reason STALE/REPORT_NOT_READY/NO_LOANS/NO_ELIGIBLE_LOANS. 적립만 가능한 경우 SAVINGS 후보 1개, 단일 분할 FAST/BALANCED/STABLE 3개. 후보 중 하나를 선택한 뒤 preview 및 PUT.
- 비교 기준: 동일 잔액·금리·기준일. 다중 후보 총 반복 월 자금=min(기존 월 추가 목표 합계, recurring_cap), 미설정은 균형 50%. 당월 가용 상한도 확인, 일회성 이월금을 반복 월 자금에 곱하지 않음. BULLET 필요 적립 우선 후 나머지는 분할상환 후보, 거치 중 제외. 적립 부족/기본 납부 불가 시 추가 축소 경고·추천 보류. 모든 후보 수수료 포함 동일 현금 cap.
- RATE_RISK: 직접 추가상환 가능한 변동금리 중 잔액 큰 순, 동률 금리 높은 순→ID; 고정은 금리 높은 순→잔액 작은 순→ID. 변동 대상 없으면 INTEREST_SAVING과 같은 결과. INTEREST_SAVING: 금리 내림차순→잔액 작은 순→ID. PARALLEL: 회차별 잔액 비례 재배분, 1원 잔여 ID순, 원금 cap. 완납 시 기존 추가 자금만 다음 대상에 배분, 정기납부액은 자동 재투입 금지.
- 비용이 모두 알려졌으면 순절감=(기준 이자−후보 이자)−(후보 수수료−기준 수수료); 하나라도 미확인 시 모든 후보 gross 이자 절감 비교, net null. 변동금리 노출≥50%이며 +1%p에 기존 추가 계획 유지 불가이고 대상 분할상환이 있으면 RATE_RISK 우선, 그 외 절감 최대, 동률 기존 적용→INTEREST_SAVING→RATE_RISK→PARALLEL. 최근 3개 완료 관측월 이행률=sum(min(해당 대출·월 실제,목표))/sum(목표)×100, 90% 이상 KEEP 판단 참고(위 위험 규칙 우선), 미적용 FIRST, 자료 부족 INSUFFICIENT_HISTORY.
- 단일 분할 PRO는 FAST/BALANCED/STABLE 후보, B/I<3% 또는 기본 불가 STABLE, 3~8% 미만 또는 선택 지출 사용률≥90% BALANCED, ≥8%이고 사용률<90% FAST. 단일 BULLET은 적립 필요액 1개 후보(SAVINGS), 직접 상환 성향 미제공; 다중에서 전체 적립만 가능한 경우 적립 후보만. 필수 데이터 부족 추천 보류. AI는 결정 코드/수치 변경 불가, 설명에만 활용, 실패 시 고정 설명.
- 후보 선택 전 아무 카드도 선택하지 않음. preview PUT 재사용, report_id + strategy_version + strategy_code 및 preview_version 검증, data_revision 포함. 단일 전략 적용은 해당 개별 계획만 변경, 다중 적용은 전체 계획 및 각 대출 동시 저장.
- 장기 변경은 다음 미도래 회차부터 새 plan_version, 과거 계획 보존. preview 저장 없음, 동일 입력 revision과 preview_version으로 저장, 최신 불일치 409 PLAN_PREVIEW_STALE/STRATEGY_STALE. 전략/전체 계획 원자적 반영; 직접 장기 수정은 다중 전략 MANUAL, 당월 배분은 변경하지 않음. 다중 PRO 전체 계획은 전략 최초 반영 이후만, 해지 시 개별 금액/기록 유지·전체/우선순위 숨김.
- 소유권·PRO 검증 및 공통 오류/금액/일자/동시성 규약 준수. 상태 변경 및 실제 기록 저장 시 공통 입력 revision 갱신, 관련 리포트 stale. GET/미리보기는 원본 변경 없음.

**화면/기능 연결:** F. PRO 단일 성향·다중 전략·적립 비교 · 추천 · 버전

### 단일 분할상환 후보 분기

- strategy_type=SINGLE_PREFERENCE, candidates는 strategy_code FAST/BALANCED/STABLE 세 개, 각 candidate schema 동일. allocations는 해당 대출 1개, priority=null. 단일 만기형 strategy_type=SAVINGS_ONLY, strategy_code=SAVINGS, allocations[].allocation_type=REPAYMENT_SAVING. 단일 적용 후 overall_plan_exists=false. 다중 전략은 기존 code 유지.
