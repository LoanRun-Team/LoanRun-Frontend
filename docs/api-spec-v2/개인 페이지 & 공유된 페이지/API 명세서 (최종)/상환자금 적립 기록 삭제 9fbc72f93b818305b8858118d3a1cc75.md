# 상환자금 적립 기록 삭제

API Endpoint: /api/repayment-savings/{saving_id}/
FE 연동: No
HTTP method: DELETE
Status: BE 구현전
Test: No
model: repayment_savings
메모: C1 / C2 적립 입력 오류 삭제
순서: 35

**기능:** 상환자금 적립 기록 삭제

**HTTP method:** `DELETE`

**API Endpoint:** `/api/repayment-savings/{saving_id}/`

**인증:** 필수 (Authorization: Bearer {access_token}) · FREE/PRO

## Request

| 필드 | Type | 필수 | 설명 |
| --- | --- | --- | --- |
| path.saving_id | integer | 필수 | 본인 적립 기록 ID |
| header.Idempotency-Key | string | 필수 | 중복 방지 |

**요청 예시**

```jsx
DELETE /api/repayment-savings/61/
Authorization: Bearer <access_token>
Idempotency-Key: demo-request-001
```

Body 없음.

**data 필드**

| 필드 | Type | 정의 |
| --- | --- | --- |
| `saving_id` | integer | 대출 상환용 적립 기록 ID |
| `deleted` | boolean | 응답 deleted |
| `loan_id` | integer | 응답 loan_id |
| `savings_balance` | integer | 해당 대출 상환 전용 적립금 잔액(원) |
| `required_monthly_saving` | integer | 만기일시상환 목표까지 필요 월 적립액(원) |
| `planned_saving_amount` | integer | 이번 달 적립 목표(원) |
| `actual_saving_amount` | integer | 이번 달 실제 적립액(원) |
| `saving_progress_pct` | number 또는 null | 적립 잔액÷현재 원금×100, 원금 0이면 null |
| `remaining_principal` | integer | 응답 remaining_principal |
| `report_stale` | boolean | 응답 report_stale |

### 실패 응답

```json
{
  "success": false,
  "code": "SAVING_CONFLICT",
  "message": "적립 잔액 또는 이미 사용된 금액과 충돌합니다.",
  "errors": {}
}
```

## `GlobalExceptionHandler.java` 처리 기준

| HTTP status | code | message |
| --- | --- | --- |
| 401 | AUTH_REQUIRED | 로그인이 필요합니다. |
| 404 | SAVING_NOT_FOUND | 리소스를 찾을 수 없습니다. |
| 400 | SAVING_VALIDATION_ERROR | 만기일시상환 적립 입력값을 확인해 주세요. |
| 409 | SAVING_CONFLICT | 적립 잔액 또는 이미 사용된 금액과 충돌합니다. |

## 처리 규칙 및 개발 참고

- 잠금 기록·이미 사용된 적립금에 영향을 주는 삭제는 409. 적립 원장과 후속 정산을 같은 트랜잭션으로 재계산.
- 만기일시상환(BULLET) 대출만 지원. 적립 기록은 실제로 돈을 모았다는 사용자 장부 입력이며 금융기관 송금이나 원금 차감 없음. 일반 저축과 구별.
- 등록/수정/삭제는 본인 활성 대출, 최신 기준 스냅샷 이후 실제 적립일(오늘 이하), 금액 1원 이상; 이미 납부에 사용한 적립금이 부족해지는 변경은 409. 등록 시 초기 적립잔액+이후 실제 적립 기록 합−실제 납부의 savings_used_amount 합으로 잔액 계산, 날짜·ID 순 replay 시 중간 음수 금지. 당월 실제 실적/정산·이월 재계산 및 리포트 stale.
- 중복 저장 Idempotency-Key, 동일 키와 본문 동일 결과, 변경 충돌 409. 삭제된 대출의 원본은 과거 분석에 보존. 적립 잔액은 원금 감소로 집계하지 않으며 계획·예산·위험도에서 동일한 원장 사용.
