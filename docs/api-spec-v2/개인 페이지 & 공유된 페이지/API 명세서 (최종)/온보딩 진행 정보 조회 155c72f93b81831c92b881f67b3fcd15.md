FE 연동: No

Status: BE 구현전
Test: No
model: onboarding
메모: A 온보딩 재진입 및 완료 상태 확인.
순서: 8

**기능:** 온보딩 진행 정보 조회

**HTTP method:** `GET`

**API Endpoint:** `/api/onboarding/`

**인증:** 필수 (Authorization: Bearer {access_token})

## Request

요청 파라미터 및 Body 없음.

**요청 예시**

```jsx
GET /api/onboarding/
Authorization: Bearer <access_token>
```

Body 없음.

## Response

### 성공 200

```json
{
  "success": true,
  "code": "ONBOARDING_DETAIL_SUCCESS",
  "message": "온보딩 진행 정보를 조회했습니다.",
  "data": {
    "completed": false,
    "registered_loan_ids": [
      1
    ],
    "finance_profile_exists": true,
    "goals_configured": false,
    "next_step": "REPAYMENT_GOAL"
  }
}
```

**data 필드** (중첩 객체는 JSON 예시와 공통 스키마 기준)

| 필드 | Type | 정의 |
| --- | --- | --- |
| `completed` | boolean | completed 값(공통 규약) |
| `registered_loan_ids` | array<integer> | 리소스 식별자 |
| `finance_profile_exists` | boolean | finance profile exists 값(공통 규약) |
| `goals_configured` | boolean | goals configured 값(공통 규약) |
| `next_step` | string | next step 값(공통 규약) |

### 실패 응답

**실패 401 · AUTH_REQUIRED**

```json
{
  "success": false,
  "code": "AUTH_REQUIRED",
  "message": "로그인이 필요합니다.",
  "errors": {}
}
```

## `GlobalExceptionHandler.java` 처리 기준

| HTTP status | code | message |
| --- | --- | --- |
| 401 | `AUTH_REQUIRED` | 로그인이 필요합니다. |

공통 예외 응답은 프로젝트 공통 규약을 따릅니다. 동일 HTTP status여도 발생 원인에 따라 code를 구분합니다.

## 처리 규칙 및 개발 참고

- next_step=LOAN, FINANCE, REPAYMENT_GOAL, COMPLETE. 기존 저장 단계 재사용. 소득 분기는 budgets/profile의 income_type; 정기 payday 필수, 비정기 예상 월 소득 및 payday=null. 상품 선택은 기존 loan-products API, 없으면 수기.

**화면/기능 연결:** A 온보딩 재진입 및 완료 상태 확인.

- 등록된 ACTIVE 대출만 온보딩 대출로 집계. 분할 약정 정책 누락 및 BULLET 목표·적립 계획 누락 시 목표 설정 단계로 이동.
