## 처리 규칙 및 개발 참고

- 상품이 선택되면 명칭 서버 조회, 미등록 상품 수기. 대출 최초 원금≥현재 잔액≥0, 만기 이전 등록, payment_day 해당 월 없는 경우 말일. 신규 기본 MATURITY 계획 생성(BULLET은 필요 적립액 포함). 201. 리포트 stale.
- 월 단위 계산: 월 이율=연 금리(%)/100/12. 원리금균등 A=P×i×(1+i)^n/((1+i)^n−1), i=0이면 P/n; 원금균등은 회차별 원금 P/n, 이자=회차 시작 잔액×i; 만기일시는 매월 이자, 만기에 잔여 원금; 거치 중 이자만, 거치 종료일 당일 또는 이후 첫 회차부터 post_grace_method 적용. BigDecimal, 원 단위 HALF_UP, 마지막 원금 잔액 정확히 정산.
- 등록 기준일·잔액 스냅샷을 보존. 등록 전 납부 이력 입력 불가. 실제 잔액 보정 시 새 스냅샷, 그 이전 납부·적립 기록 읽기 전용; 후속 원본 기록을 실제 일자·ID 오름차순으로 재처리. 과거 금리·회차 확정 기준 보존.
- 분할상환 및 거치 후 분할(거치 종료 이후)은 prepayment_policy 필수: KEEP_PAYMENT는 원래 기본 월 원리금(원리금균등) 또는 고정 월 원금(원금균등)을 유지하여 완납일 단축, KEEP_MATURITY는 약정 만기까지 남은 회차를 기준으로 월 기본액 재계산. BULLET은 null. 거치 중 추가상환 계획 없음, 약정상 허용한 실제 중도상환 기록 가능.
- 시뮬레이션에서 회차 시작 잔액으로 이자 계산 → 기본 정기 납부 → 추가원금 반영. 실제 추가원금은 기록 즉시 잔액 차감, 이번 회차 이자 유지, 다음 회차부터 감소 잔액. 약정 다음 정기 납부액(contractual_monthly_payment)은 해당 회차 완료 판단용 우선값, 미래 모든 회차에 복제 금지.
- 활성 대출 최대 7개; 지원 방식 4종, loan_form=GENERAL; 원금이 0이고 확인된 미납 이자·비용도 0이면 PAID, 향후 일정 제거. 삭제 DELETED(일반 조회·미래 계산 제외, 과거 실적 보존), 삭제를 완납으로 계산하지 않음.
- 개인 금리 수기 입력(MANUAL), 금감원 공시는 상품 참고용. 변동금리 이력 적용일 이후 첫 납부 회차부터 적용, 실제 과거 납부 금액 변경 금지. 시뮬레이션은 현재 금리 유지. 연체이자·일할이자·실제 송금 제외.
- 예상 중도상환수수료는 MORTGAGE/JEONSE에서 확인된 약정 조건만 계산. prepayment_fee_method=FIXED(추가원금×수수료율/100), LINEAR(동일 금액×잔여 부과기간 일수/전체 부과기간 일수, 0~1 cap), NONE(면제 확인, 0), UNKNOWN(null). fee_start_date와 fee_end_date는 부과 기간, 종료일 이후 0. 약정 면제 확인 시 0; 약정상 다른 조건/미확인은 null. 수수료를 추가 자금에 포함, 실제 수수료는 모든 대출에서 입력 가능. 실제 비용은 원금 감소에 포함하지 않음.
- BULLET: target_payoff_date≤계약 만기, 목표일까지 남은 적립 회차 n에 대해 required_monthly_saving=ceil(max(잔액−적립 잔액,0)/n), n=0이면 즉시 부족액(회차 없음), 마지막 회차 cap. 실제 적립은 원금·이자 감소 없음. 실제 납부에서 적립금 사용액만 차감, 실제 조기/완납 전까지 이자 지속.
- 소유권·PRO 검증 및 공통 오류/금액/일자/동시성 규약 준수. 상태 변경 및 실제 기록 저장 시 공통 입력 revision 갱신, 관련 리포트 stale. GET/미리보기는 원본 변경 없음.

**화면/기능 연결:** A S-01d / C1-d. 최초 원금·잔액 분리, 상품 미등록 시 수기.

- BULLET의 초기 확보 적립금은 등록 시 initial_savings_balance로 저장하며 기존 확보 잔액으로만 계산. 등록 이전 거래나 당월 소득/저축/적립 실적으로 집계하지 않음.
