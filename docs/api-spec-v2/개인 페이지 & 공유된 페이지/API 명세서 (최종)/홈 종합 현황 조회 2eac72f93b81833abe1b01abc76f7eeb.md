## `GlobalExceptionHandler.java` 처리 기준

| HTTP status | code | message |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 입력값을 확인해 주세요. |
| 401 | `AUTH_REQUIRED` | 로그인이 필요합니다. |
| 404 | `LOAN_NOT_FOUND` | 대출을 찾을 수 없습니다. |

공통 예외 응답은 프로젝트 공통 규약을 따릅니다. 동일 HTTP status여도 발생 원인에 따라 code를 구분합니다.

## 처리 규칙 및 개발 참고

- 활성 대출 원금 합계/최초 원금 기반 진행률, 완납 상태 표시. checklist는 정기 다섯 상태, 별도 추가/적립 목표는 미납과 무관. 월 통계·적립·위험 요약 같은 서비스 계산. 무료 위험·리포트 잠금, 날짜/N 숨김. PRO report_[status.is](http://status.is)_new는 최신 완료 및 stale=false 생성 24시간 이내.
- 정기 납부 상태 UPCOMING(당일까지 기록 없음), PAID(필요액 충족), PARTIAL(부분 기록, 경과 후에도 부분), UNRECORDED(납부일 경과 무기록), UNPAID(사용자가 미납 확인). display_status는 동일 5종. 추가 상환 목표 부족은 미납 아님. 미기록 모달 닫기는 상태 변경 없음. 실제 미납 확인은 별도 PATCH, 이후 완전 납부 시 PAID. 정기 회차는 예정일 귀속, 실제 실적·지출은 paid_at 월 귀속. 지연 일수=max(0,paid_at−due_date); 연체이자 없음.
- B(available_cash)=계획 소득−고정 필수−변동 필수−선택−일반 저축−정기 부담(이전 미충족 포함, 당월 이미 지급분 중복 차감 금지, 만기 원금은 기존 적립 사용 부분 제외). 음수 허용, deficit=max(−B,0). allocation_capacity=max(B+carry_in,0). recurring_cap=max(B,0). 위험 산정은 이월 전 B. 실제 현금흐름은 실제/가정 수령, 확인 지출 및 실제 납부·적립만 별도 계산; 미확인 실제값 null. 적립금에서 지급한 원금은 실제 월 현금지출에서 중복 제외.
- 리포트는 첫 진입 또는 관련 데이터 revision/완료월/동의 변경(stale) 시 POST 요청, GET 조회 전용. 변경 없으면 기존 완료 결과 반환, 생성 중이면 동일 job/report_id 반환, FAILED 재시도 60초 제한, 일괄 자동 배치 없음. 생성 중 입력 바뀌면 result stale, 최신 표시 금지. 홈 is_new는 최신 완료 생성 24시간 이내+stale=false; FREE는 잠금 및 날짜/N 숨김. AI는 서버 확정 수치·전략 코드 해석/문구만, 실패 시 기본 문구로 대체.
- 소유권·PRO 검증 및 공통 오류/금액/일자/동시성 규약 준수. 상태 변경 및 실제 기록 저장 시 공통 입력 revision 갱신, 관련 리포트 stale. GET/미리보기는 원본 변경 없음.
