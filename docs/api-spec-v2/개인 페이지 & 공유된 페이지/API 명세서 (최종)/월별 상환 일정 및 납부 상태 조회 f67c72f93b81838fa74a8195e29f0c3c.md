**HTTP method:** `GET`

**API Endpoint:** `/api/payments/schedule/`

**인증:** 필수 (Authorization: Bearer {access_token})

## Request

| 필드 | Type | 필수 | 설명 |
| --- | --- | --- | --- |
| `query.month` | string(YYYY-MM) | 필수 | 조회할 월 |
| `query.loan_id` | integer | 선택 | 없으면 전체 대출 |

**요청 예시**


## 처리 규칙 및 개발 참고

- due_items는 해당 월 약정 납부날짜 순→loan_id→due_item_id. calendar_events는 예정/실제 납부/적립 구분. monthly_totals 완료/전체/부족액은 정기 회차 기준, 실제 합계는 실제 납부일. 적립은 별도 항목, 정기 상태에 영향 없음.
- 납부 기록은 실제 날짜(오늘 이하)·금액·REGULAR/EXTRA 선택. total amount=principal_amount(정기 원금)+extra_amount(추가 원금)+interest_amount+fee_amount; 기본 자동 분리 후 실제 은행 내역으로 정정 가능한 네 항목, 정정 시 네 항목 모두 제공하고 합계 검증. 공통 기본 충당 순서 비용→이자→원금; 확인된 실제 내역 우선. REGULAR은 가장 오래된 미충족 회차부터 충당(복수 회차), 초과분의 추가 원금이 실제 확인될 때만 추가로 구분. 확인되지 않은 초과액은 정정 안내 후 저장 거부. EXTRA는 별도 추가 상환이며 정기 상태를 바꾸지 않음. 잔액 초과 원금·미확인 구성·미래 날짜 거부.
- 정기 납부 상태 UPCOMING(당일까지 기록 없음), PAID(필요액 충족), PARTIAL(부분 기록, 경과 후에도 부분), UNRECORDED(납부일 경과 무기록), UNPAID(사용자가 미납 확인). display_status는 동일 5종. 추가 상환 목표 부족은 미납 아님. 미기록 모달 닫기는 상태 변경 없음. 실제 미납 확인은 별도 PATCH, 이후 완전 납부 시 PAID. 정기 회차는 예정일 귀속, 실제 실적·지출은 paid_at 월 귀속. 지연 일수=max(0,paid_at−due_date); 연체이자 없음.
- 등록/수정/삭제는 최신 잔액 스냅샷 이후 원본만 가능. 실제 납부일·ID순 replay, 기존 확정 회차/약정 금리 보존. 변경한 실제 기록과 관련 현재 잔액·누적 실적·월말 정산·이후 이월금·리포트 stale을 트랜잭션 처리. 여러 동일 날짜/금액 납부 허용; Idempotency-Key로 중복 차단. 적립금 출금은 savings_used_amount로 명시, 해당 대출의 실제 원금 납부에만 사용(원금 이하, 적립 잔액 이하), 수정/삭제 시 적립 원장도 재계산.
- 소유권·PRO 검증 및 공통 오류/금액/일자/동시성 규약 준수. 상태 변경 및 실제 기록 저장 시 공통 입력 revision 갱신, 관련 리포트 stale. GET/미리보기는 원본 변경 없음.
