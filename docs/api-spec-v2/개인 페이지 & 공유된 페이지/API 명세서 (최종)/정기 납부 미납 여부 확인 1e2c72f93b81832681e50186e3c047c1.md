## `GlobalExceptionHandler.java` 처리 기준

| HTTP status | code | message |
| --- | --- | --- |
| 401 | AUTH_REQUIRED | 로그인이 필요합니다. |
| 404 | DUE_ITEM_NOT_FOUND | 리소스를 찾을 수 없습니다. |
| 400 | DUE_CONFIRMATION_VALIDATION_ERROR | 기한 경과한 미기록 회차만 미납 확인할 수 있습니다. |
| 409 | DUE_CONFIRMATION_CONFLICT | 납부 상태가 변경되었습니다. 다시 조회해 주세요. |

## 처리 규칙 및 개발 참고

- true는 납부일이 지난 실제 기록 없는 UNRECORDED(또는 기존 UNPAID 반복)에만 허용. false는 미납 확인을 취소해 UNRECORDED로 복귀. PAID/PARTIAL/UPCOMING에는 확인 불가. 부족한 부분 납부는 PARTIAL 유지.
- 확인만으로 납부 기록 생성·잔액 차감하지 않음. 실제 납부했다면 POST /api/payments/ 사용. 모달 닫기는 API 호출하지 않음. 이후 기록이 완전 충족되면 PAID, 일부면 PARTIAL. 사용자 확인 상태와 리포트 revision을 원자적 저장.
- 정기 납부 상태 UPCOMING(당일까지 기록 없음), PAID(필요액 충족), PARTIAL(부분 기록, 경과 후에도 부분), UNRECORDED(납부일 경과 무기록), UNPAID(사용자가 미납 확인). display_status는 동일 5종. 추가 상환 목표 부족은 미납 아님. 미기록 모달 닫기는 상태 변경 없음. 실제 미납 확인은 별도 PATCH, 이후 완전 납부 시 PAID. 정기 회차는 예정일 귀속, 실제 실적·지출은 paid_at 월 귀속. 지연 일수=max(0,paid_at−due_date); 연체이자 없음.
