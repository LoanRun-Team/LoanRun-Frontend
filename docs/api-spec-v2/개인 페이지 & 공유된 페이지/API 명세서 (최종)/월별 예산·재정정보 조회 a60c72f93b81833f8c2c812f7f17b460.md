**기능:** 월별 예산·재정정보 조회

**HTTP method:** `GET`

**API Endpoint:** `/api/budgets/{year_month}/`

**인증:** 필수 (Authorization: Bearer {access_token})

## Request

| 필드 | Type | 필수 | 설명 |
| --- | --- | --- | --- |
| `path.year_month` | string(YYYY-MM) | 필수 | 조회 월 |

**요청 예시**

```jsx
GET /api/budgets/2026-11/

```

## `GlobalExceptionHandler.java` 처리 기준

| HTTP status | code | message |
| --- | --- | --- |
| 400 | `INVALID_MONTH` | 월 형식을 확인해 주세요. |
| 401 | `AUTH_REQUIRED` | 로그인이 필요합니다. |

공통 예외 응답은 프로젝트 공통 규약을 따릅니다. 동일 HTTP status여도 발생 원인에 따라 code를 구분합니다.

## 처리 규칙 및 개발 참고

- 과거 월 read-only, 미래 월은 예측만. 실제 미확인은 null, 기본 소득·지출 예상은 별도. 정기 납부와 목표는 payment/plan 조회 결과 사용.
- 월별 기본값 DEFAULT 매월 1일 예상 생성; INPUT은 사용자 확인 지출, 과거 월 수정 불가. 기본 재정정보 변경은 현재·미래 미확정 월만. 정기 계획 소득은 월 기본 실수령액+확인 추가입금, 지급일 전 기본 소득 실제 수령으로 간주하지 않고 이후 ASSUMED 표시. 비정기 계획은 직전 3개 확인 완료 월 평균(부족 시 온보딩 예상), 실제는 입금 기록만; 미확인과 실제 0 구분. 선택 지출 월 시작 한도 스냅샷 고정. 확인 실제 지출 없으면 절약액 null, 있으면 max(한도−실제,0).
- B(available_cash)=계획 소득−고정 필수−변동 필수−선택−일반 저축−정기 부담(이전 미충족 포함, 당월 이미 지급분 중복 차감 금지, 만기 원금은 기존 적립 사용 부분 제외). 음수 허용, deficit=max(−B,0). allocation_capacity=max(B+carry_in,0). recurring_cap=max(B,0). 위험 산정은 이월 전 B. 실제 현금흐름은 실제/가정 수령, 확인 지출 및 실제 납부·적립만 별도 계산; 미확인 실제값 null. 적립금에서 지급한 원금은 실제 월 현금지출에서 중복 제외.
- 당월 총 배분=추가 상환 예산(예상 수수료 포함)+BULLET 적립+reserve_amount; 각 목표는 월 전체 금액, 이미 사용한 현금 추가원금·수수료 및 적립을 계산하여 미사용 잔여 배분 검증. 총합은 cap 이하, 미배분 허용·예비비로 자동 배정 금지. 월 저장값 우선, 없으면 장기 목표 초기값 및 부족 경고. 해당 월만 적용, 원금 및 장기 전략 불변.
- 월말 정산은 확인된 실제 수령/지출/일반 저축/실제 현금 납부(적립 사용 차감)/적립금과 carry_in으로 계산. 양수면 reserve_settled=min(reserve_amount,실제 잉여), carry_out=max(실제 잉여−reserve_settled,0). 적자/자료 부족은 자동 이월 없음. carry_out은 다음 달만, 소득에 합산 금지. 일반저축·비상금·예비비·대출별 적립·이월금 분리, 자동 합산/사용 금지. 과거 납부 정정은 실적/정산 및 연쇄 이월 재계산.
- 소유권·PRO 검증 및 공통 오류/금액/일자/동시성 규약 준수. 상태 변경 및 실제 기록 저장 시 공통 입력 revision 갱신, 관련 리포트 stale. GET/미리보기는 원본 변경 없음.
