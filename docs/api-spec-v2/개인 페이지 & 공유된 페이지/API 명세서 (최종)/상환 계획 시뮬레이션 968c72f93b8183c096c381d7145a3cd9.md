**기능:** 상환 계획 시뮬레이션

**HTTP method:** `POST`

**API Endpoint:** `/api/repayment-plans/preview/`

**인증:** 필수 (Authorization: Bearer {access_token})

## Request

| 필드 | Type | 필수 | 설명 |
| --- | --- | --- | --- |
| `plans` | array<object> | 조건부 | 직접/성향 입력일 경우 1개 이상. STRATEGY 분기에서는 생략 |
| `plans[].loan_id` | integer | 필수 | 인증 사용자 활성 대출 ID |
| `plans[].mode` | string | 조건부 | 직접 분기 MATURITY/PREFERENCE/TARGET_DATE/EXTRA_AMOUNT/MONTHLY_AMOUNT |
| `plans[].preference` | string 또는 null | 조건부 | PREFERENCE이면 FAST, BALANCED, STABLE 중 하나 |
| `plans[].target_date` | string(date) 또는 null | 조건부 | TARGET_DATE 또는 일시형 목표일(기본 MATURITY는 만기) |
| `plans[].extra_monthly_payment` | integer 또는 null | 조건부 | EXTRA_AMOUNT일 때 0 이상, 장기 목표 초과는 경고 |
| `plans[].monthly_amount` | integer 또는 null | 조건부 | MONTHLY_AMOUNT일 때 월 총 납부액(원) |
| `report_id` | integer | 조건부 | 전략 분기에서 필수(최신 완료 리포트) |
| effective_date | string(date) 또는 null | 선택 | 적용일; 생략 시 다음 납부일 |
| `strategy_code` | string | 조건부 | 전략 분기 RATE_RISK/INTEREST_SAVING/PARALLEL 또는 단일 FAST/BALANCED/STABLE/SAVINGS |
| `strategy_version` | string | 조건부 | 전략 후보 버전, 전략 분기 필수 |
| `plans[].planned_saving_amount` | integer 또는 null | 조건부 | BULLET은 목표일까지 자동 역산; 직접 월 적립 설정 시 입력(원) |

**요청 예시**

```jsx
POST /api/repayment-plans/preview/
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
{
  "plans": [
    {
      "loan_id": 1,
      "mode": "EXTRA_AMOUNT",
      "extra_monthly_payment": 100000
    }
  ],
  "effective_date": "2026-11-25"
}
```

**전략 분기 요청 예시**

```json
{
  "report_id": 101,
  "strategy_code": "INTEREST_SAVING",
  "strategy_version": "strategy-v3-demo"
}
```

## 처리 규칙 및 개발 참고

- POST 두 분기(plans 배열 또는 report_id+strategy_code+strategy_version), preview_version 발급. 저장 없음. current_plans/proposed_plans, 공통 기준 delta, warnings. 직접 재정 부족은 경고 후 저장 가능; 계약 자체 불가능한 목표만 PAYOFF_NOT_FEASIBLE. 단일 PRO FAST/BALANCED/STABLE 또는 SAVINGS 후보도 같은 전략 분기 사용.
- 장기 목표(target_payoff_date)와 실제 속도 기준 projected_payoff_date 분리. target_date는 사용자 입력 목표, estimated_payoff_date 호환 키=projected_payoff_date. 계획 미리보기에는 제안 계획 기준 예상일도 별도 표시. 목표일은 계약 만기 이내, 목표일 역산은 공통 엔진 최소 월 추가액. 계산 자체 불가능한 목표는 오류, 재정 여유 초과 장기 목표는 부족액 경고 후 저장 가능. 기본 약정·기록 변경 없음.
- FAST/BALANCED/STABLE=전체 반복 월 배분 가능액의 80/50/0%, HALF_UP 원 단위(5만원 내림 없음), 전체 가계 기준 한 번만 계산; 여러 대출은 지정 배분 합계 검증. 저장 목표액은 변경 전까지 유지. 월 배분만 변경하면 해당 월만 override, 장기 목표/전략 변경 없음. 거치 중 추가 계획 없음, 만기일시 target 및 적립 목표 별도.
- 가계 recurring_cap=max(B,0), B는 이월 전 재정 잔여액. 당월 배분 cap은 이월 포함 및 이미 실제 사용/적립한 자금 고려. 장기 재정 부족 경고만, 전략 실제 적용과 당월 override는 cap 이하. 대출별 금액은 기본 빚 및 적립·수수료를 구분.
- 계획 진행률은 계획 버전 시작 잔액을 동일 분모로 계획/실제 누적 원금 감소 비교. 홈 동심원은 최초 원금 대비 감소. 이번 달과 누적 도래회차 계획·실적 구분. track.status=ON_TRACK/BEHIND/AHEAD 정확한 금액 비교, 정기 무기록이면 UNRECORDED 별도; 실제 확인 미납·부분은 regular_due_status 별도. 확인 부족은 null/INSUFFICIENT; 도래 목표 0원은 비율 null. BULLET은 적립 목표 vs 적립 실적, 원금 진행 별도 표시. projected=최근 6개 완료 관측 월 실제 추가원금 평균(1~5개면 해당 평균, 0개면 계획 기준 FALLBACK_PLAN), 미기록 월 제외, 실제 0월 포함. BULLET은 실제 적립 평균 사용; 계약 만기에 자금 부족 시 null/부족 경고.
- 장기 변경은 다음 미도래 회차부터 새 plan_version, 과거 계획 보존. preview 저장 없음, 동일 입력 revision과 preview_version으로 저장, 최신 불일치 409 PLAN_PREVIEW_STALE/STRATEGY_STALE. 전략/전체 계획 원자적 반영; 직접 장기 수정은 다중 전략 MANUAL, 당월 배분은 변경하지 않음. 다중 PRO 전체 계획은 전략 최초 반영 이후만, 해지 시 개별 금액/기록 유지·전체/우선순위 숨김.
- 비교 기준: 동일 잔액·금리·기준일. 다중 후보 총 반복 월 자금=min(기존 월 추가 목표 합계, recurring_cap), 미설정은 균형 50%. 당월 가용 상한도 확인, 일회성 이월금을 반복 월 자금에 곱하지 않음. BULLET 필요 적립 우선 후 나머지는 분할상환 후보, 거치 중 제외. 적립 부족/기본 납부 불가 시 추가 축소 경고·추천 보류. 모든 후보 수수료 포함 동일 현금 cap.
- RATE_RISK: 직접 추가상환 가능한 변동금리 중 잔액 큰 순, 동률 금리 높은 순→ID; 고정은 금리 높은 순→잔액 작은 순→ID. 변동 대상 없으면 INTEREST_SAVING과 같은 결과. INTEREST_SAVING: 금리 내림차순→잔액 작은 순→ID. PARALLEL: 회차별 잔액 비례 재배분, 1원 잔여 ID순, 원금 cap. 완납 시 기존 추가 자금만 다음 대상에 배분, 정기납부액은 자동 재투입 금지.
- 비용이 모두 알려졌으면 순절감=(기준 이자−후보 이자)−(후보 수수료−기준 수수료); 하나라도 미확인 시 모든 후보 gross 이자 절감 비교, net null. 변동금리 노출≥50%이며 +1%p에 기존 추가 계획 유지 불가이고 대상 분할상환이 있으면 RATE_RISK 우선, 그 외 절감 최대, 동률 기존 적용→INTEREST_SAVING→RATE_RISK→PARALLEL. 최근 3개 완료 관측월 이행률=sum(min(해당 대출·월 실제,목표))/sum(목표)×100, 90% 이상 KEEP 판단 참고(위 위험 규칙 우선), 미적용 FIRST, 자료 부족 INSUFFICIENT_HISTORY.
- 단일 분할 PRO는 FAST/BALANCED/STABLE 후보, B/I<3% 또는 기본 불가 STABLE, 3~8% 미만 또는 선택 지출 사용률≥90% BALANCED, ≥8%이고 사용률<90% FAST. 단일 BULLET은 적립 필요액 1개 후보(SAVINGS), 직접 상환 성향 미제공; 다중에서 전체 적립만 가능한 경우 적립 후보만. 필수 데이터 부족 추천 보류. AI는 결정 코드/수치 변경 불가, 설명에만 활용, 실패 시 고정 설명.
- 후보 선택 전 아무 카드도 선택하지 않음. preview PUT 재사용, report_id + strategy_version + strategy_code 및 preview_version 검증, data_revision 포함. 단일 전략 적용은 해당 개별 계획만 변경, 다중 적용은 전체 계획 및 각 대출 동시 저장.
- 소유권·PRO 검증 및 공통 오류/금액/일자/동시성 규약 준수. 상태 변경 및 실제 기록 저장 시 공통 입력 revision 갱신, 관련 리포트 stale. GET/미리보기는 원본 변경 없음.
